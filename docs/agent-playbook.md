# Регламент для AI-агентов

Общие правила для агента **любой** роли. Промт конкретной роли — в [`docs/prompts/`](prompts/). Человеку достаточно сказать агенту: «прочитай `docs/agent-playbook.md` и `docs/prompts/<твоя роль>-wave2.md` и работай по ним».

## Продукт и сроки

Пользователь вводит название вуза и за 30 секунд получает профиль: фото кампуса, общежитий, аудиторий, библиотек и города + фильтры «Общежитие», «Спорт», «Лаборатории», «Студенческая жизнь». У каждого фото — ссылка на источник, дата с типом и уровень доверия с доказательствами. Главный критерий жюри — точность: честное «не нашли» лучше чужого фото.

- **Заморозка функций:** пятница 19:00 (Астана). **Сдача:** суббота 19.09, 12:00.
- Только **бесплатные** API: Gemini (бесплатный тариф), Serper, Openverse, Wikimedia, Upstash.
- Прод: https://campusproof.vercel.app · здоровье: `/api/health`.

## Что прочитать перед кодом

1. `AGENTS.md` — правила, стек, зоны ответственности.
2. `docs/module-map.md` — твои файлы и их точные сигнатуры.
3. `lib/types.ts` — контракты данных.
4. Саму задачу: `gh issue view <N> --comments` (комментарии новее текста задачи).

## Как брать задачу

1. `git fetch origin && git switch main && git pull --rebase origin main`.
2. `gh issue view N --comments`:
   - закрыта или по ней влит PR → **пропусти**;
   - назначена на другого человека → **пропусти, это его задача**;
   - свободна → `gh issue edit N --add-assignee @me` + комментарий «Взял в работу, ветка `<имя>`».
3. Если в задаче вдруг оказалось два исполнителя — остаётся тот, чей комментарий «Взял» раньше; второй снимает себя и берёт следующую.
4. Ветка от свежего `main`: `git switch -c p<N>/<короткое-имя>`.
5. Код + тесты → `npm run fix` → `npm run check` (должен пройти полностью).
6. `git push -u origin HEAD` → `gh pr create` (тело по-русски по `.github/pull_request_template.md`, первая строка `Closes #N`) → `gh pr merge --auto --squash` → `gh pr checks --watch` → дождись **MERGED**.
7. Комментарий в задаче: что сделано и как проверить.

Одна задача = один PR до ~400 строк. Большую задачу дели: в промежуточных PR пиши «Part of #N», в последнем — «Closes #N». **Не откладывай вливание на конец** и не жди чужую задачу: пропусти её и вернись позже.

## Когда свои задачи кончились

Не простаивай и не придумывай новые функции — бери из общей очереди по порядку:

1. `gh issue list --state open --label bug --search "no:assignee"` — баги, сначала ломающие демо.
2. `gh issue list --state open --label must --search "no:assignee"` — критический путь любой роли.
3. `gh issue list --state open --label B-layer --search "no:assignee"`.
4. Если пусто: `node scripts/qa/smoke.mjs --base https://campusproof.vercel.app`, заведи issues на найденное и почини то, что в твоей зоне.

## Перехват чужой зоны

Файлы закреплены за ролями (`AGENTS.md` → Ownership), но **задача важнее зоны**: свободную задачу другой роли из критического пути брать можно и нужно. Назначил себя — файлы этой задачи твои до мержа PR. Файлы задач, которые уже кто-то взял, не трогай.

## Жёсткие правила (нарушение может стоить дисквалификации)

- Никаких особых случаев под конкретный вуз: ни зашитых фото, ни белых списков, ни «демо-университетов».
- Баллы и уровни считает только `lib/scoring` по записанным доказательствам. Модель сообщает наблюдения, а не вердикт.
- Никакого фейкового прогресса: события стрима отражают реальную работу. Фикстуры и реплей — только dev и превью.
- У каждого показанного фото есть `sourcePageUrl` (страница, которую пайплайн реально открыл) и `retrievedAt`.
- Кешированный профиль помечен как сохранённый, с исходным временем. Деградированные профили не кешируются.
- Никаких стоков и парсинга Google Images / Instagram / Facebook / VK / 2GIS.
- Vision не опознаёт людей; крупные портреты исключаются.
- `.env*` и `.vercel/` не открывать и не печатать. Ключи вставляет человек.
- Не пушить в `main` и не делать force-push.

## Бесплатные квоты

- Автотесты **никогда** не ходят в настоящие API: фейки и сохранённые ответы.
- Ручная проверка — на 1–2 вузах; результаты кешируй через `lib/cache/kv.ts`.
- HTTP 429 = квота кончилась: не повторять в цикле, честно деградировать.

## Одна папка — один агент

В одной папке репозитория работает только один агент. Второму — отдельный worktree: `git worktree add ../campusproof-<имя> -b <ветка>` (`docs/team-workflow.md` §4). Иначе два агента смешают незакоммиченные изменения друг друга.

## Заморозка (пятница 19:00)

- К этому времени всё влито; ничего важного не лежит только на одном компьютере.
- Незаконченный компонент не должен рендерить заглушку — пусть возвращает `null`; нереализованный источник убрать из `lib/pipeline/deps.ts`.
- После заморозки: только исправления багов, README, слайды, видео и репетиция.

## Конец сессии

`git push` своей ветки, комментарий-handoff в задаче (шаги в `.claude/skills/cp-handoff/SKILL.md`) и короткий отчёт человеку: какие PR влиты, что не успел и почему.
